# 报告写作阶段 LLM 指引规约 v2

> 适用场景：阶段 5（文字报告撰写）。
> 前置条件：阶段 0-4 全部完成，数据差距与数据需求问题已解决，数据准备就绪。
> 与 references/audience-adaptation.md（受众语言矩阵）、references/07-报告模板.md（输出结构）配合使用。

## 〇、输入清单与权威层级（写作前必须全部加载）

| 输入文件 | 在写作阶段的角色 |
|---|---|
| report.yml | **最高约束**。目标、受众、禁区、成功标准；已锁定，冲突时停下上报，不得自行变通 |
| 06-分析大纲.md | **论证骨架**。结论、发现、参照系、章节安排均以此为准；写作 = 扩写骨架，不是另起炉灶 |
| 05-数据质量报告与口径确认.md | **口径与数字的法定出处**。术语表、data_asof、「能用但打折」清单 |
| 01-分析框架与数据需求.md | 口径定义表的补充来源；假设清单（与 06 验证结果对照） |
| 03-数据差距说明.md | 残余缺口的声明义务来源 |
| 02-建模决策单.md | 若建模：业务化翻译要求与可解释性约束 |
| 数据包本体 | 唯一事实来源 |
| 04-数据需求文件.md / 00-进度状态.md | 写作阶段不直接使用；00 用于收尾时更新进度 |

**权威冲突处理**：文件之间口径矛盾时，优先级 = report.yml > 05（签字口径）> 01（框架口径）> 其他。发现矛盾不得自行取舍，记录并上报用户。

## 一、硬约束检查（动笔前逐项过，违反即重写）

1. **禁区扫描**：对照 `report.yml compliance`：
   - `cannot_quote` 列出的数据，全文（含附录、图表注释）零出现；
   - `cannot_conclude` 列出的结论，全文无任何变相表述（含"可能意味着"级别的暗示）。
2. **脱敏要求**：按 04 号的数据脱敏约定执行（如有）。
3. **成功标准回查**：`success_criteria.required_conclusions` 中每条必要结论，必须在报告中有明确落点；`arguments` 中标记 `ignorable_if` 的，先核对忽略条件是否成立，成立才可省略并在附录注明。
4. **范围对齐**：全文时间范围、业务线、地理范围不得超出 `report.yml scope`。

## 二、骨架继承与校验（第 1 步，替代"生成骨架"）

06 号大纲即骨架。动笔前只做三件事：

1. **覆盖性校验**：`required_conclusions` × 大纲「核心结论 draft」做映射矩阵——每条必要结论有归属，每个大纲结论有必要性。出现孤儿（大纲里有、成功标准里没有的结论），检查是否值得保留，不值得就删。
2. **假设一致性校验**：06 号「假设验证结果」中被推翻的假设，其下游结论必须已从大纲移除或修正；遗留即报错。
3. **参照系完备性校验**：大纲中每个「结论｜参照系」对，参照系为空的必须补齐（环比/同比/预算/外部基准四选一），补不齐的降级为推断级或删除。

校验通过后才允许进入撰写。**骨架层面的修改（增删结论、改章节顺序）不属于写作阶段权限，需回到阶段 4 并告知用户。**

## 三、边界规约（防幻觉、防越界）

1. **唯一事实来源**：正文数字只能来自数据包本体；外部数字只能来自 06 号「外部信息清单」。禁止引入任何其他来源的统计值、行业"常识"。
2. **引用外部信息必须携带清单中的两个字段**：时效（数据年份）+ 可比性说明。清单里没有可比性说明的外部数据，禁止使用。
3. **缺口显式化**：03 号残余缺口、06 号「仍存在的数据缺口」，原样继承到报告「局限」章与相关发现中，禁止脑补填充。
4. **数字可溯源**：草稿阶段每个数字标注来源（数据表/查询 ID 或外部清单行号），终稿转为"来源"标注。

## 四、论证规约（数据如何变成论断）

1. **确定性三级表达**，用词严格分级：

   | 级别 | 适用 | 标志词 |
   |---|---|---|
   | 事实 | 数据直接呈现 | "数据显示""为" |
   | 解读 | 有参照系的比较结论 | "表明""高于/低于" |
   | 推断 | 因果或趋势外推 | "可能意味着""一个解释是" |

   推断级内容必须在「局限与风险」章有对应条目。

2. **形容词必须量化**："大幅""显著""领先""恶化"等词后必须跟数字；给不出就删词。
3. **因果克制**：相关性 ≠ 因果；除非有建模结果（且已完成业务化翻译）或机制证据，统一用推断级表达。
4. **反证义务**：每条核心发现自查"还有别的解释吗"，有则写入「反证与替代解释」。优先检查：该发现是否依赖某个被标记「能用但打折」的数据。

## 五、表达规约（语言一致性）

1. **术语对齐**：指标名称、口径以 **05 号口径确认单（签字版）为唯一标准**；05 未覆盖的指标用 01 号口径定义表。全文不造同义词。
2. **数字格式**：金额单位全文统一；同类指标小数位一致（默认 1 位）；区分"百分点"与"%"；≥5 位数加千分位。
3. **时效锚点**：报告 frontmatter 的 `data_asof` 取 05 号「数据提取时间」；涉及时效表述（"最新""目前"）一律换成该锚点的绝对日期。
4. **句式**：一段一个论点，先结论后证据；单句 ≤40 字为优。
5. **禁用词表**（出现即重写）：赋能、抓手、助力、打造、众所周知、毋庸置疑、势在必行、一定程度上、某种意义上。
6. **篇幅配额**：按 06 号大纲中结论的优先级分配篇幅（`success_criteria.arguments` 的 核心/重要/可选 ≈ 5:3:2），禁止平均用力。
7. **读者立场适配**（来自 `report.yml reader_context`）：
   - `known`：读者已知的不再论证，一句带过；
   - `stance`：与读者倾向相反的结论，证据链写全并前置反证；
   - `persuasion`：优先使用能说服该读者的证据形态（数字/案例/对标）。
8. **风格基准**：`report.yml benchmark` 有指定时，先读标杆报告，对齐其详略与语气。
9. **反填空**：不得机械对应模板字段；相邻发现重叠时合并或交叉引用；字段无内容写"无"并说明原因。

## 六、特殊情形规约

1. **「能用但打折」映射清单**（强制）：05 号质量问题清单中每项"能用但打折"，建立映射表——该数据用在哪个发现/章节 → 对应章节必须有局限声明。成稿后逐项核对，漏声明即不通过。
2. **若建模**（02 号决策为"建模"）：
   - 模型结论必须完成业务化翻译（哪些因素影响最大、影响多少、建议怎么调整），禁止直接出现"特征重要性""AUC"等术语而不加业务解释；
   - 模型相关结论整体按推断级表达处理；
   - 附录必须包含验证方式与验证结果摘要。
3. **被推翻假设的处理**：若推翻本身有决策价值（如"市场并未萎缩"推翻了立项假设），可在发现中保留一条，但表述为"原计划基于 X 假设，数据显示该假设不成立"。

## 七、生成过程（三步，禁止单次成稿）

- **第 1 步**：骨架继承与校验（见第二节）。产出：校验记录 + 必要结论覆盖矩阵。
- **第 2 步**：数字台账。列出全文将用的全部数字：

  | 数值 | 单位 | 口径（05/01 出处） | 来源编号 | 计划出现位置 |
  |---|---|---|---|---|

  成文后逐项回查：正文数字与台账一致？台账数字全部用上？正文出现而台账没有的数字 = 幻觉信号，立即核查。
- **第 3 步**：分章撰写 + 终稿通读。逐章写，一致性以骨架与台账为基准；终稿通读只改三类问题：数字一致性、术语一致性（对 05 号签字口径）、前后论断矛盾。最后执行模板文末自检清单 + 本规约第一节硬约束复查。

## 八、评审回路（对接决策门 D）

初稿完成后启动评审（独立 prompt），产出写入「评审意见记录」：

> 你是一位挑剔的 [report.yml audience.primary 对应角色]。阅读以下报告，只做三件事：
> 1. 列出你读完仍存疑的论断及原因（对照你的立场：{reader_context.stance}）；
> 2. 指出数字、术语、逻辑的任何前后不一致；
> 3. 指出任何"看起来正确但没有信息量"的句子。
> 不重写，只输出问题清单。

问题清单回喂写作 LLM 逐条修订；修订稿连同评审记录提交用户确认（决策门 D）。

## 九、收尾

- 若触发了骨架修改或禁区冲突，在 00 号「变更记录」中登记：时间、原因、涉及阶段。
