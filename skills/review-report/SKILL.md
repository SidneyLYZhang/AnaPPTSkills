# Review Report

以**挑剔的评审人**身份复核整份报告。核心信条：**审的是结论—证据链，不是校对**——错别字格式是最低价值的一层，真正决定质量的是每条结论有没有被数据扎实支撑。产出一份可执行的 `_审校报告.md`，作为后续优化的唯一工作队列。

可独立使用（对任意已完成的文字报告 / PPT），也在 `analysis-report-builder` 交付后作为更深的整体审校补其决策门 D 与阶段 6 对账之不足。

## 交互原则

1. **不改稿，只审**：只输出问题与修订动作，重不重写由用户决定。
2. **按风险定级**：先判报告档位，再决定清单做到哪一层——内部草稿全套审会拖垮节奏，对外发布连形式层都不能省。
3. **换眼破盲区**：作者对自己的内容有补全盲区，眼睛会跳过脑中原意；关键一轮必须用没参与写作的独立视角复看。
4. **断点友好**：多轮审校按轮次追加写入，不覆盖历史；重跑读 `_报告进度.md` 定位最新报告版本。

## 总体流程

```
定范围与定级 → 载入锚点 → 五层审查（文字 + PPT + 两者对齐）
        → 换眼复核（独立 subagent）→ 落盘 _审校报告.md → 优化回路
```

---

## 第 1 步：定范围与定级

确认审校对象（文字版报告？PPT？两者？各自版本/路径），并按 `report.yml` 用途判风险档位：内部草稿 / 内部决策 / 对外发布·财务合规·学术。

**完成条件**：审校对象与档位确定；按档位定出本轮执行到第几层（映射见 `references/review-checklist.md` 末节强度分级）。

## 第 2 步：载入锚点

加载并交叉对齐：`report.yml`（成功标准 / 禁区 / scope / audience）、06 号大纲（结论骨架与参照系）、05 号口径确认（数字法定出处）、阶段 5 数字台账、文字报告全文、PPT 全量文案（含备注）。以这些为"事实与口径的账本"，不引入清单外来源。

**完成条件**：必要结论清单、口径表、数字台账三张锚点就位，作为后续逐项核对的基准。

## 第 3 步：五层审查

加载 `references/review-checklist.md`，按优先级逐层过：一 硬伤 → 二 逻辑与结论 → 三 完整性与一致性 → 四 受众与风险 → 五 形式。对**文字报告、PPT、以及两者之间的一致性**分别过一遍。执行三则贯穿：**亲算而非重看**（关键数字亲手重算）、**换媒介**（导纯文本/打印来读）、**清单化打钩**。每个发现标 **必改 / 建议 / 可选**，记位置、依据锚点、修订动作、回 builder 的哪个阶段。

**完成条件**：清单 1–17 每项有结论（含"通过/不适用"），每条必要结论过得了"反方视角"一问，文字↔PPT 与数字台账一致。

## 第 4 步：换眼复核（独立 subagent）

主 agent 派一个**不共享写作上下文**的 subagent 冷读全稿。subagent 只拿读者/审计立场，不预知第 5 步要写文件，逼它把问题挖尽。prompt：

> 你是一位挑剔的 [report.yml audience.primary 角色]，读到这份报告（文字 + PPT 文案）要据它做决策。只输出问题清单，不改写：① 仍存疑的论断及原因（对照立场 {reader_context.stance}）；② 数字/口径/术语/逻辑的任何前后不一致；③ 结论超出数据支持、估计推测被写成事实之处；④ 看起来正确但无信息量的句子；⑤ 若我是审计/竞对，最可能从哪里攻这个结论。

**完成条件**：换眼清单回收，与第 3 步发现合并去重，冲突或新增项补入问题表。

## 第 5 步：落盘 `_审校报告.md`

按 `assets/templates/审校报告.md` 写出本轮结果：总体判定 + 问题清单表 + 五层逐项结论 + 高频翻车点专项 + 换眼复核记录 + 按严重度排序的**优化队列**。多轮追加为"轮次 N"，不覆盖历史。

**完成条件**：文件写入报告项目目录；必改/建议/可选计数清晰；每条问题有可执行修订动作与回退阶段。

## 第 6 步：优化回路

向用户呈现总体判定与必改项摘要。据优化队列回到 `analysis-report-builder` 对应阶段（结论/证据问题回阶段 4–5，呈现/文字↔PPT 回阶段 6，形式回阶段 5/7）修订；改完可重跑本技能进入新一轮，直到必改为零。更新 `_报告进度.md` 记录本轮审校与状态。
