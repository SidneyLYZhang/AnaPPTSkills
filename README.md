# AnaPPTSkills

一套面向**经营 / 咨询分析报告**的 AI Agent 技能集（Skills），让 LLM 以"分析负责人 + 数据分析师"的身份，按标准化 SOP 与用户协作完成一份分析报告——从需求承接到文字报告，再到 PPT 交付。

## 这个项目是什么

AnaPPTSkills 不是可执行程序，而是两个可被 AI Agent（如 Trae、Claude Code 等）加载的 **Skill**。每个 Skill 通过 `SKILL.md` 声明触发条件、交互原则与执行步骤，并附带模板与参考文档。Agent 在对话中识别到用户意图后，按 Skill 定义的结构化流程推进工作。

## 解决什么问题

写分析报告常见三类痛点：

1. **需求不清就开干**——目标受众、决策场景、成功标准没对齐，返工率高。
2. **流程不可控**——没有质量门，建模与否凭感觉，初稿评审流于形式。
3. **断点难续**——多轮对话后状态丢失，换个会话就得从头讲背景。

本项目用一份 SOP + 两个 Skill 来对症：

- **grill 追问机制**：阶段 0-1 反复追问直到 `report.yml` 锁定，答不出"给谁看 / 为什么现在做 / 要什么结论 / 何时交付"四问不进入下一步。
- **四个决策门**（A 受众分层、B 建模评估、C 框架评审、D 初稿评审）作为质量刹车。
- **断点续跑**：每步产出物写入 `_报告进度.md`，新会话读取后从断点继续。
- **建模默认不做**：除非目标类型 + 数据条件 + 交付约束三列都满足，否则不上模型，避免可解释性下降。

## 包含的 Skill

### 1. `setup-anappt`——项目初始化

触发词："初始化报告项目""创建分析项目""开始一个新的分析报告"等。

创建标准目录结构：

```
<目标目录>/
├── report.yml           ← 报告设定文件（阶段 0-1 填充并锁定）
├── _报告进度.md           ← 断点续跑状态文件
└── data/                ← 用户数据文件目录
```

### 2. `analysis-report-builder`——报告构建主流程

触发词："做一份分析报告""经营分析""业务分析""专题分析""竞品分析""按 SOP 走报告流程"等。

按 7 个阶段 + 4 个决策门推进：

```
阶段0-1 需求承接（grill 追问）→ report.yml
        ↓
【决策门A】受众分层与报告形态
        ↓
阶段2 分析框架与数据需求（咨询式 / 经营式 / 混合）
        ↓
【决策门B】是否建模（默认否）→【决策门C】框架评审
        ↓
阶段3 数据准备与确认 → 阶段4 外部信息+初步验证+大纲
        ↓
阶段5 文字版报告 v1.0 →【决策门D】初稿评审
        ↓
阶段6 PPT → 阶段7 优化交付 + 复盘沉淀
```

每阶段动作：说明目标 → 按模板产出交付物 → 自查完成条件 → 呈现用户确认 → 更新进度文件。

## 安装

提供两种安装方式，任选其一即可。

### 方式一：使用 `npx skills add`（推荐）

在终端执行以下命令，将本仓库的两个 Skill 注册到当前 AI Agent（如 Trae、Claude Code）：

```bash
# 从 GitHub 仓库安装
npx skills add https://github.com/sidneylyzhang/AnaPPTSkills

# 或从本地路径安装（已克隆仓库后）
npx skills add ./AnaPPTSkills
```

执行完成后，`setup-anappt` 与 `analysis-report-builder` 会自动注册到 Agent 的 Skills 列表。

### 方式二：让 Agent 自主完成安装

在对话中直接对 Agent 说：

> "请帮我安装 AnaPPTSkills https://github.com/sidneylyzhang/AnaPPTSkills 这个技能集"

Agent 会识别意图，自主调用 `npx skills add` 完成安装与注册。

## 如何使用

1. **加载 Skill**：参照上方 [安装](#安装) 章节任选一种方式完成注册。
2. **初始化项目**：在对话中触发 `setup-anappt`，在工作目录生成 `report.yml`、`_报告进度.md` 与 `data/`。
3. **构建报告**：触发 `analysis-report-builder`，按阶段 0-1 开始 grill 追问。每阶段确认后自动推进。
4. **中断与续跑**：随时可说"停""改需求""回到阶段X"。新会话只需再次触发主 Skill，会读取进度文件从断点继续。

## 关键特性

- **结论先行**：文字版报告与 PPT 均遵循金字塔结构，标题即结论。
- **受众适配**：管理层 / 业务人员 / 外部人员三套篇幅、语言、证据强度规范，同一份结论按受众裁剪呈现。
- **建议可执行**：每条建议指明"谁、做什么、何时、预期效果"。
- **数据可追溯**：每个数字回溯到阶段 3 的数据快照，每个外部信息标注来源与时效。
- **复盘沉淀**：阶段 7 输出可复用模板、口径、踩坑清单，询问是否入库。

## 语言

默认简体中文。报告正文遵循"结论 + 影响 + 建议"的表达顺序，少术语；管理层版术语带解释、数字有参照系。
