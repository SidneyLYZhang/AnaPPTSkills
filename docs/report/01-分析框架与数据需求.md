# 分析框架 与 数据需求清单

> 阶段 2 产出物。验收：每个子问题都有方法；每个方法都有数据支撑或明确的代理方案。

## 一、报告类型与框架选择

- **报告类型**：☑ 混合（以咨询式框架驱动为主，"快速上手"章节用操作流程描述）
- **选用方法及理由**：
  - **对标分析**（咨询式）：用于"与同类工具的差异与优势"章节。对比对象为 3 个同类 PPT skill + 通用 AI PPT 工具 + 传统报告 SOP。理由：读者核心决策是"是否采用本项目"，对标分析能直观呈现差异点与定位。
  - **假设检验树**（咨询式）：用于"解决什么问题"章节。将"AnaPPTSkills 解决报告三大痛点"作为核心假设，拆解为可证伪子假设（需求不清、流程不可控、断点难续），用项目文档中的 SOP 机制作为证据。
  - **痛点-方案映射**（通用问题树）：用于"是什么/不是什么"+"解决什么问题"章节。把报告写作痛点映射到 AnaPPTSkills 的对应机制。
  - **操作流程描述**（非分析框架，用于"快速上手"章节）：按 README 三步法直接呈现安装与使用步骤，不做分析论证。
  - **金字塔原理**（通用）：全文结构强制遵守，结论先行，每层 MECE。

## 二、外部搜索决策（阶段 2 新增）

- **是否需要阶段 2 外部搜索**：☑ 是
- **判断依据**：报告目标含"与同类工具的差异与优势"，外部信息是核心输入；且主受众为小白，需要外部锚点建立认知。
- **搜索结果摘要**（已在阶段 0-1 完成）：
  1. **ppt-master（hugohe3）**：AI 从文档生成原生 PowerPoint。Python 工作流，输出 .pptx。核心=原生 PPT 对象深度（slide masters/shapes/charts）。侧重"还原 PowerPoint 原生能力"。
  2. **dashi-ppt-skill（chuspeeism）**：职场 PPT Skill。12 套主题/1020 版式/8576 控件/浏览器编辑控制台，Node.js，输出 HTML+PDF+PPTX。侧重"视觉主题丰富+生成后可编辑"。AnaPPTSkills 阶段 6 推荐配合此 skill。
  3. **guizang-ppt-skill（op7418）**：单文件 HTML 横向翻页 PPT。两套视觉系统（电子杂志+瑞士国际主义），npx skills add 安装，输出单文件 HTML。侧重"强设计风格+叙事表达"。
  4. **通用 AI PPT 工具**（Gamma、Tome、ChatGPT 直接生成）：一键生成，无流程管控，无需求追问，无断点续跑。
  5. **传统报告写作 SOP**（纯人工+模板）：依赖个人经验，规范性、可复现性弱。
- **核心洞察**：三个同类 PPT skill 均聚焦"如何把内容做成好看的 PPT"（视觉生成层）；AnaPPTSkills 聚焦"如何从需求承接到交付一份完整报告"（流程管控层），PPT 仅是末段。**与 dashi-ppt 是互补关系**（AnaPPTSkills 管流程与内容，dashi 管视觉），非竞争。

## 六、风险与假设

- **数据不可得风险与降级方案**：
  - 风险：同类工具仅调研了 README，未深入 SKILL.md 细节，对比可能遗漏内部机制差异。
  - 降级：对比以 README 公开信息为准，对未深入部分明确标注"基于公开 README"，不下绝对结论。
- **本框架依赖的关键假设**（将在阶段 4 初步验证）：
  - 假设1：AnaPPTSkills 的"流程管控层"定位与同类 PPT skill 的"视觉生成层"定位确实存在显著差异（可通过功能对比验证）。
  - 假设2：报告写作三大痛点（需求不清、流程不可控、断点难续）是业务分析人员的真实痛点（基于 README 声明与行业常识，阶段 4 用项目自身 SOP 设计反证）。
  - 假设3：小白用户按 README 三步可完成首次使用（基于 README 清晰度，阶段 4 用模拟走查验证）。
